Documentation · 2.3.1

Build complete WordPress sites, section by section, with the LLM of your choice.

Créez des sites WordPress complets, section par section, avec le LLM de votre choix.

Naano WP is an AI-powered visual builder that lives entirely inside your WordPress admin. You bring your own API key. No external backend, no subscription, no data leaves your server other than the prompt itself.

Naano WP est un constructeur visuel propulsé par l'IA qui vit entièrement dans votre administration WordPress. Vous apportez votre propre clé API. Pas de backend externe, pas d'abonnement, aucune donnée ne quitte votre serveur hormis le prompt lui-même.

Most AI builders send the whole page to the model on every change. Naano WP flips that: only the section you're editing travels as full HTML. Every other section is compressed to an 8-character hash placeholder. That single decision shapes the rest of the product — faster iteration, cheaper tokens, calmer reasoning, more focused output.

La plupart des constructeurs IA envoient la page entière au modèle à chaque modification. Naano WP inverse cette logique : seule la section en cours d'édition transite en HTML complet. Toutes les autres sections sont compressées en un simple hash de 8 caractères. Ce choix architectural façonne tout le reste du produit — itérations plus rapides, tokens moins coûteux, raisonnement plus ciblé, résultats plus précis.

This guide walks through every feature: installing the plugin, configuring a provider, generating a page, editing sections individually, swapping elements via the new ♻ recycle button, publishing, translating, and extending. Each topic stands alone — jump straight to what you need from the left.

Ce guide couvre chaque fonctionnalité : installation du plugin, configuration d'un fournisseur, génération d'une page, édition section par section, remplacement d'éléments via le nouveau bouton ♻, publication, traduction et extension. Chaque sujet est autonome — naviguez directement vers ce dont vous avez besoin depuis la barre gauche.

Installation #

Installation #

Two paths: upload the zip through the WordPress admin, or drop the folder into /wp-content/plugins/ via FTP.

Deux options : téléverser le zip depuis l'administration WordPress, ou déposer le dossier dans /wp-content/plugins/ via FTP.

  1. Download the latest release

    Grab the naano-ai-website-builder.zip from the project's GitHub releases. Click the Download 2.3.1 button in the top-right of this page.

  2. Upload to WordPress

    In the admin sidebar, go to Plugins → Add New Plugin → Upload Plugin. Pick the zip you just downloaded and click Install Now, then Activate.

  3. Configure your provider

    A new menu appears in the sidebar: Naano AI Builder. Open Settings, pick a provider (Claude, Gemini, OpenAI, Kimi, or DeepSeek), paste your API key, and click Test connection to confirm the credentials.

  4. You're ready

    That's it — no additional server configuration required. Naano WP works out of the box on any standard WordPress host, including shared hosting. Go to Naano AI Builder → AI Pages and create your first page.

  1. Télécharger la dernière version

    Récupérez le fichier naano-ai-website-builder.zip depuis les releases GitHub du projet. Cliquez sur le bouton Download 2.3.1 en haut à droite de cette page.

  2. Téléverser sur WordPress

    Dans la barre latérale de l'administration, allez dans Extensions → Ajouter une extension → Téléverser une extension. Sélectionnez le zip que vous venez de télécharger, cliquez sur Installer maintenant, puis sur Activer.

  3. Configurer votre fournisseur

    Un nouveau menu apparaît dans la barre latérale : Naano AI Builder. Ouvrez Réglages, choisissez un fournisseur (Claude, Gemini, OpenAI, Kimi ou DeepSeek), collez votre clé API et cliquez sur Tester la connexion pour valider les identifiants.

!

Updating from a previous version

Mise à jour depuis une version précédente

WordPress caches plugin assets with the plugin's version string. After upgrading, the browser may still serve the old builder.js. Deactivate the old version, install the new zip, then hard-reload the builder page (Cmd/Ctrl + Shift + R).

WordPress met en cache les assets du plugin avec son numéro de version. Après la mise à jour, le navigateur peut continuer à servir l'ancien builder.js. Désactivez l'ancienne version, installez le nouveau zip, puis rechargez la page du builder en force (Cmd/Ctrl + Shift + R).

Concept

The section-by-section model #

Le modèle section par section #

A single architectural decision shapes the entire product. Here's what changes when you stop sending whole pages to the model.

Une seule décision architecturale façonne tout le produit. Voici ce qui change quand on arrête d'envoyer des pages entières au modèle.

Conventional AI website builders treat the page as one atomic unit. Each change retypes the entire page in the prompt, the entire page in the response. Naano WP works the other way around. The page is a list of sections. Only one section is in-context at any time.

Les constructeurs de sites IA classiques traitent la page comme une unité atomique. Chaque modification retranscrit la page entière dans le prompt, et la page entière dans la réponse. Naano WP fait l'inverse : la page est une liste de sections, et une seule section est en contexte à la fois.

What the model actually sees

Ce que le modèle voit réellement

When you ask Naano WP to refine the Hero, the prompt contains:

Quand vous demandez à Naano WP d'affiner le Hero, le prompt contient :

  • The full HTML of the Hero (what you're editing)
  • An ordered list of hash placeholders for every other section — eight-character fingerprints that preserve position without spending tokens on content
  • Your instruction
  • The last three user/assistant exchanges (for continuity)
  • Design variables, references, and asset citations
  • Le HTML complet du Hero (ce que vous éditez)
  • Une liste ordonnée de hash placeholders pour toutes les autres sections — des empreintes de 8 caractères qui préservent la position sans dépenser de tokens sur le contenu
  • Votre instruction
  • Les trois derniers échanges utilisateur/assistant (pour la continuité)
  • Les variables de design, références et citations d'assets

The model returns just the new Hero. Everything else is untouched on the server side.

Le modèle retourne uniquement le nouveau Hero. Tout le reste est inchangé côté serveur.

The numbers

Les chiffres

i

70–90% tokens saved

70–90 % de tokens économisés

Section placeholders compress every untouched section to ~8 characters. Cumulative savings across an editing session are dramatic.

Les placeholders de sections compriment chaque section non modifiée à ~8 caractères. Les économies cumulées sur une session d'édition sont considérables.

ii

3 exchanges of context

3 échanges de contexte

The conversation history is trimmed to the last three round-trips. Old context is pruned automatically; cost stays bounded.

L'historique de conversation est limité aux trois derniers allers-retours. L'ancien contexte est élagué automatiquement ; le coût reste maîtrisé.

iii

1 LLM call per tick

1 appel LLM par tick

The WP-Cron runner generates one section at a time, never running long enough to trip a shared-host execution ceiling.

Le runner WP-Cron génère une section à la fois, sans jamais tourner assez longtemps pour déclencher les limites d'exécution d'un hébergement mutualisé.

iv

Skip-on-fail

Passe-en-cas-d'échec

If a section's worker is killed, the runner persists what it had, advances, continues. No single section can take down a whole page.

Si le worker d'une section est interrompu, le runner persiste ce qu'il avait, avance et continue. Aucune section ne peut faire échouer toute une page.

The section is not a performance optimisation. It's a unit of attention — yours, and the model's.
La section n'est pas une optimisation de performance. C'est une unité d'attention — la vôtre, et celle du modèle.
Concept

The WP-Cron runner #

Le runner WP-Cron #

A small state machine that turns a long generation into a chain of short, recoverable ticks.

Une petite machine à états qui découpe une génération longue en une chaîne de ticks courts et récupérables.

Shared hosts kill long-running PHP processes. LSAPI_MAX_PROCESS_TIME caps execution. max_execution_time caps execution. Memory limits cap execution. A naive site generator that issues twelve sequential LLM calls in one request will run for one or two minutes and die before it finishes.

Les hébergements mutualisés interrompent les processus PHP trop longs. LSAPI_MAX_PROCESS_TIME limite l'exécution. max_execution_time aussi. Les limites mémoire aussi. Un générateur naïf qui émet douze appels LLM séquentiels dans une seule requête tournera une à deux minutes avant de mourir avant la fin.

Naano WP sidesteps the problem entirely. When you click Generate full website, the AJAX handler:

Naano WP contourne entièrement ce problème. Quand vous cliquez sur Générer le site complet, le handler AJAX :

  1. Creates a job in a transient (a small object: cursor, sections, log, status).
  2. Schedules the first WP-Cron tick.
  3. Returns a job_id immediately.
  1. Crée un job dans un transient (un petit objet : curseur, sections, journal, statut).
  2. Programme le premier tick WP-Cron.
  3. Retourne immédiatement un job_id.

Each tick does one thing: call the LLM for one section, sanitise the response, store it, advance the cursor, schedule the next tick. The browser polls naano_poll_job every couple of seconds for progress. No server-side configuration is required — WP-Cron fires automatically on incoming page requests, which is standard WordPress behaviour.

Chaque tick fait une seule chose : appeler le LLM pour une section, assainir la réponse, la stocker, avancer le curseur, programmer le tick suivant. Le navigateur interroge naano_poll_job toutes les deux secondes pour suivre la progression. Aucune configuration serveur n'est requise — WP-Cron se déclenche automatiquement sur les requêtes entrantes, ce qui est le comportement standard de WordPress.

If the worker is killed mid-tick — host timeout, memory exceeded, anything — the next tick reads the persisted state and continues from where the cursor stopped. The section that failed gets recorded in _naano_failed_sections with a reason. You see it as an entry in the Failed sections drawer with a one-click Retry. A site with twelve sections will never die on one bad section.

Si le worker est interrompu en plein tick — timeout de l'hébergeur, mémoire dépassée, autre — le tick suivant relit l'état persisté et reprend là où le curseur s'était arrêté. La section échouée est enregistrée dans _naano_failed_sections avec une raison. Elle apparaît dans le panneau Sections échouées avec un bouton Réessayer en un clic. Un site de douze sections ne peut jamais échouer à cause d'une seule mauvaise section.

Le bouton ♻ Nouveau 2.3.1#

A second hover affordance — alongside the section "+", smaller, scoped to a single element. One click and you swap the element for a fresh widget.

What happens on click

Ce qui se passe au clic

A modal opens with two cards: Text and Image. Pick one and the element is replaced in place — same position, same parent, AI-generated classes preserved so the new widget sits visually inside the section's existing layout.

Une modale s'ouvre avec deux cartes : Texte et Image. Choisissez-en une et l'élément est remplacé sur place — même position, même parent, classes générées par l'IA préservées pour que le nouveau widget s'intègre visuellement dans la mise en page existante de la section.

The text widget

Le widget Texte

Replaces the element with a <p> containing the placeholder string "Texte à éditer…". The paragraph inherits the original element's classes (minus inspect-mode helpers) and is immediately editable — click it to start typing right away.

Remplace l'élément par un <p> contenant la chaîne placeholder "Texte à éditer…". Le paragraphe hérite des classes de l'élément original (sans les helpers du mode inspection) et est immédiatement éditable — cliquez dessus pour commencer à taper.

The image widget

Le widget Image

Closes the modal and opens the WordPress media library directly. Pick an image; on select the element is replaced with an <img> whose src and alt are pulled from the attachment. max-width: 100% and height: auto are applied inline so the image scales correctly inside any layout.

Ferme la modale et ouvre directement la médiathèque WordPress. Choisissez une image ; à la sélection, l'élément est remplacé par un <img> dont le src et l'alt sont tirés de la pièce jointe. max-width: 100% et height: auto sont appliqués en inline pour que l'image s'adapte correctement à n'importe quelle mise en page.

What's preserved, what's not

Ce qui est conservé, ce qui ne l'est pas

  • Kept: AI-generated class names — the widget keeps the layout context (grid placement, alignment, etc.).
  • Dropped: Inline style attribute, data-naano-el id, custom CSS attribute. The widget starts visually clean and gets a new id on the next click-to-select.
  • Section dirty: The replacement is broadcast to the parent via the same naano-element-html-updated message used by every other DOM mutation — the section is marked unsaved, the toolbar's Save changes button appears.
  • Conservé : les noms de classes générés par l'IA — le widget garde le contexte de mise en page (placement grille, alignement, etc.).
  • Supprimé : l'attribut style inline, l'id data-naano-el, l'attribut CSS personnalisé. Le widget repart propre et reçoit un nouvel id au prochain clic.
  • Section modifiée : le remplacement est diffusé au parent via le même message naano-element-html-updated utilisé par toute autre mutation DOM — la section est marquée non sauvegardée, le bouton Enregistrer les modifications apparaît.

Designed to coexist with existing affordances

Conçu pour coexister avec les affordances existantes

The recycle button has its own hover scope (the hovered element), its own click handler (opens the widget modal, not the element editor), and its own z-index. None of the existing builder behaviours change — the section "+" button, inspect mode click-to-edit, inline contenteditable typing, all work exactly as before.

Failed sections & retry #

Sections échouées & réessai #

A dedicated drawer for the sections that didn't survive their first generation.

Un panneau dédié aux sections qui n'ont pas survécu à leur première génération.

When a worker is killed mid-tick, the runner persists what it had, records the failure in _naano_failed_sections post meta (with a reason), and advances. Failed sections appear in a dedicated Failed sections drawer field with a one-click Retry button per entry. Each retry triggers a fresh single-section generation; recovered sections clear from the list automatically.

Quand un worker est interrompu en plein tick, le runner persiste ce qu'il avait, enregistre l'échec dans la post meta _naano_failed_sections (avec une raison) et avance. Les sections échouées apparaissent dans un champ dédié Sections échouées avec un bouton Réessayer en un clic par entrée. Chaque réessai déclenche une nouvelle génération de section unique ; les sections récupérées disparaissent automatiquement de la liste.

This means: a host kill during generation is not catastrophic. You finish the rest of the page, then come back to the failed sections one at a time when the host is calmer.

Cela signifie qu'une interruption par l'hébergeur pendant la génération n'est pas catastrophique. Vous terminez le reste de la page, puis revenez aux sections échouées une par une quand l'hébergeur est plus calme.

Troubleshooting #

Résolution de problèmes #

The small set of problems that come up regularly, and how to fix them.

Les problèmes qui reviennent régulièrement, et comment les résoudre.

The recycle button doesn't appear after updating

Le bouton ♻ n'apparaît pas après la mise à jour

The browser is serving the old builder.js from cache. WordPress version-strings every asset URL (builder.js?ver=…) — if the version is the same as before, browsers reuse the cached file. Bump NAANO_VERSION in the main plugin file, or hard-reload the builder page (Cmd/Ctrl + Shift + R).

Le navigateur sert l'ancien builder.js depuis le cache. WordPress ajoute la version du plugin dans chaque URL d'asset (builder.js?ver=…) — si le numéro de version est identique, le navigateur réutilise le fichier en cache. Incrémentez NAANO_VERSION dans le fichier principal du plugin, ou rechargez la page du builder en force (Cmd/Ctrl + Shift + R).

Generation is stuck on "queued"

La génération reste bloquée sur « en attente »

The WP-Cron tick hasn't fired yet. Visiting any front-end URL on your site will trigger WordPress's request-based cron and unblock the queue. If the issue persists, check that outbound HTTPS to your LLM provider is allowed by your host's firewall.

Le tick WP-Cron n'a pas encore été déclenché. Visiter n'importe quelle URL publique de votre site déclenchera le cron basé sur les requêtes WordPress et débloquera la file. Si le problème persiste, vérifiez que les connexions HTTPS sortantes vers votre fournisseur LLM ne sont pas bloquées par le pare-feu de l'hébergeur.

A section failed during generation

Une section a échoué pendant la génération

Look for the Failed sections drawer field at the bottom of the left drawer. Each entry has a Retry button. Most failures are transient (host kill, LLM rate limit) and succeed on retry.

Cherchez le champ Sections échouées en bas du panneau gauche. Chaque entrée possède un bouton Réessayer. La plupart des échecs sont transitoires (interruption par l'hébergeur, limite de débit LLM) et réussissent au second essai.

The API key test fails

Le test de clé API échoue

Click Test connection in Settings — the response contains the provider's actual error message. The most common causes are (1) wrong region for Gemini, (2) expired or rotated keys, (3) outbound firewall blocking HTTPS to the provider.

Cliquez sur Tester la connexion dans les Réglages — la réponse contient le message d'erreur exact du fournisseur. Les causes les plus fréquentes sont : (1) mauvaise région pour Gemini, (2) clé expirée ou révoquée, (3) pare-feu bloquant les connexions HTTPS sortantes vers le fournisseur.

Published page looks different from the preview

La page publiée est différente de l'aperçu

The preview iframe and the published page use the same assembled HTML, including the body-margin reset and your global CSS. If they diverge, the most likely cause is an active WordPress theme injecting styles. Naano WP publishes pages as raw HTML with no theme wrapping — if your theme is intercepting page rendering through filters, you may need to whitelist Naano WP-published pages.

L'iframe d'aperçu et la page publiée utilisent le même HTML assemblé, incluant la réinitialisation des marges et votre CSS global. Si une divergence apparaît, la cause la plus probable est un thème WordPress actif qui injecte des styles. Naano WP publie les pages en HTML brut sans encapsulation par le thème — si votre thème intercepte le rendu via des filtres, vous devrez peut-être mettre les pages Naano WP en liste blanche.
